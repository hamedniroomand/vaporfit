# Why vaporfit

## Vapor mode

Vue 3.6 brings Vapor mode.
You add one attribute, `<script setup vapor>`, and the component compiles to code that updates the DOM directly.
There is no virtual DOM (VDOM) for that component.
The goal is faster updates and a smaller bundle.

You can use Vapor in two ways:

| Way     | The app                                         | Use                                                                   |
| ------- | ----------------------------------------------- | --------------------------------------------------------------------- |
| Interop | `createApp()` with `vaporInteropPlugin`         | Vapor components and VDOM components work together. Migrate in steps. |
| Pure    | `createVaporApp()`, with no VDOM runtime loaded | Each component in the tree is Vapor. This gives the smallest bundle.  |

The [Vue 3.6 release notes](https://github.com/vuejs/core/releases/tag/v3.6.0-rc.14) describe Vapor mode.

## The problem

Not every feature and not every library works in a Vapor component yet.
Some failures show an error. You see them and you repair them.

Many failures show nothing:

- The build passes.
- The console is empty.
- Vue prints no warning.
- A directive does not run, or a listener is not on the element.

One example is `as-child` from Reka UI with Vue 3.6.0-rc.14 or older.
In a Vapor component, the button gets no attributes and no click listener.
A click does nothing.
The [Reka UI report](/upstream/reka-ui-as-child) has the steps.
Vue 3.6.0-rc.15 fixes this problem.

You find a failure of this type in production, or a user finds it.

## What vaporfit does

vaporfit reads the files of your project. It does not run the app.
It gives each component a verdict before you change the component: `ready`, `blocked`, or `unknown`.

- **It finds the failures that give no error.** A finding shows the file, the line and the rule.
- **It knows the libraries.** The [library table](/libraries) has 25 Vue libraries, with the verified version, the statement of the maintainers and the known broken features.
- **Each claim has evidence.** A row gets its data from a probe that runs in a real browser, a maintainer text, or an issue link.
- **It follows the chain.** A cause that is two wrappers away from your page shows at your page, with the path to the library.
- **It plans the migration.** The report ranks the rules that hold back the most components and gives an order: convert the leaves first.
- **It makes the safe changes.** `vaporfit fix --write` adds `vapor` to each component that is ready.

## What vaporfit does not do

`ready` means that vaporfit found no known problem. It does not test behavior.
When the data does not prove a problem, the verdict is `unknown`, not `ready`.
The [limitations](/guide/limitations) page lists each limit.

## Start

```sh
npx vaporfit
```
