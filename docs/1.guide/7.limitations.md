# Limitations

This page lists each limit of version 0.1.
vaporfit reads the project files.
A clean result is not a test of the application.

## Pure Vapor tier

Each component has a `pure` verdict.
`ready` needs an interop verdict of `ready`.
`ready` also needs every resolved child to be a Vapor component, or a local `.vue` file whose own `pure` verdict is `ready`.
A top-level `await` in `<script setup>` makes `pure` `blocked`.
An unresolved tag makes `pure` `unknown`.
A Nuxt project is not pure `ready`.
The text report ranks the causes that keep the VDOM runtime.

## Codemods

`vaporfit fix` adds `vapor` to a ready component.
`vaporfit fix` removes `v-memo` on a component that receives `vapor` in that same run.
`vaporfit fix --router` changes `$route` to `useRoute()` and `$router` to `useRouter()`.
`vaporfit fix --i18n` changes `$t`, `$d`, `$n`, `$te`, and `$tm` to `useI18n()`.
`--i18n` runs only when the tool can see `legacy: false`.
The tool does not change a file it marks manual.
The tool does not rewrite other names.

## No behavior test

The tool does not run the application.
The tool does not compare a Vapor result with a VDOM result in the project.
A probe under `repros/` is a separate check.
That probe is not a test of the project.

## Ready

"ready" means that vaporfit found no known problem.
"ready" does not mean that the component works.
The tool does not test behavior.

## Schema version 0

The report field `schemaVersion` has the value `0`.
Schema version 0 is unstable.
A later release can change the fields.

## Nuxt tag resolution

The tool reads Nuxt component names from `.nuxt/components.d.ts`.
The test of this read uses the fixture `test/fixtures/nuxt-tags`.
The tool does not run a Nuxt build for this test.

## Imported props types

The tool reads a props type that a component imports with a relative path.
A props type that a component imports with a path alias or from a package gives a compile error.
The verdict of that component is `unknown`.
