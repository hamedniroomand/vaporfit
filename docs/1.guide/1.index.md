# Get started

vaporfit checks the components in a Vue project and reports the problems it knows about.
Vue 3.6 can compile a component that has `<script setup vapor>` and print nothing when a feature is skipped.
New to Vapor mode? Read [Why vaporfit](/guide/why) first.

## Run the check

Run this command in a Vue project:

```sh
npx vaporfit
```

The report gives each component an interop verdict and a pure verdict.
Each verdict is `ready`, `blocked`, or `unknown`.
A finding in a component shows the file, the line, and the rule.
Some findings also show a chain of components.

## Commands

| Command  | Function                                               |
| -------- | ------------------------------------------------------ |
| `check`  | Check the project. This is the default.                |
| `fix`    | Print the changes. Add `--write` to write the files.   |
| `ui`     | Open the [local report](/guide/ui).                    |
| `report` | Write a [static report](/guide/report). Use `--out`.   |
| `mcp`    | Serve the report to an [agent](/guide/mcp) over stdio. |
| `help`   | Show the help.                                         |

## Options

| Option            | Function                                                                                          |
| ----------------- | ------------------------------------------------------------------------------------------------- |
| `--i18n`          | Change `$t`, `$d`, `$n`, `$te`, and `$tm` to `useI18n()`. Use this option only with `fix`.        |
| `--json`          | Print the JSON report.                                                                            |
| `--out <dir>`     | Write the static report in this directory. Use this option only with `report`.                    |
| `--root <dir>`    | Set the project root. The default is the current directory.                                       |
| `--router`        | Change `$route` and `$router` to `useRoute()` and `useRouter()`. Use this option only with `fix`. |
| `--strict`        | Exit with 1 for each blocked component.                                                           |
| `--write`         | Write the files. Use this option only with `fix`.                                                 |
| `--version`, `-v` | Print the version.                                                                                |
| `--help`, `-h`    | Show the help.                                                                                    |

## Exit codes

| Code | Cause                                                                                                                |
| ---- | -------------------------------------------------------------------------------------------------------------------- |
| `0`  | No component that has `vapor` is blocked. The plugin finding is not an error.                                        |
| `1`  | A component that has `vapor` is blocked, or the plugin finding is an error, or `--strict` finds a blocked component. |
| `2`  | The input is not valid.                                                                                              |

## Ready

"ready" means that vaporfit found no known problem.
It does not test behavior.
The [limitations](/guide/limitations) page lists each limit.
